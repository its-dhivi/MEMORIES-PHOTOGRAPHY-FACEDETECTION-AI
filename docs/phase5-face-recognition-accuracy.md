# Phase 5: face recognition accuracy and reliability

> **Current workflow note (2026-11-27):** Historical event-level approval instructions below are superseded. Owners/admins can privately search without an event approval record. Public guest matching requires system-level model validation and the event's Enable Face Matching switch. Legacy approval columns remain for database compatibility and are not consulted.

## Production assessment

The implementation has improved coverage and diagnosis, but **recognition accuracy is not yet validated for weddings or production guest delivery**. The supplied ControlFace10K benchmark is synthetic and single subject. Its held-out pair precision at the existing 0.64 similarity threshold was only 38 true positives against 136 false positives (21.84%). Public matching remains disabled until system-level representative evaluation is complete. The synthetic benchmark does not qualify. Private owner/admin searches do not expose results to guests.

## Pipeline audit and root causes

| Stage                 | Finding and action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decode/orientation    | Pillow signature decoding, EXIF transpose, pixel and byte limits, and RGB conversion were already present. Added an orientation regression test. Sharp generates oriented derivatives from originals.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| DSLR derivatives      | The AI input was limited to 2048 pixels on its longest side. Small group faces could disappear before detection. Increased the cap to 4096; originals remain private and unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Detection             | A single YuNet pass on a resized image missed small faces. Photo analysis now combines a bounded global pass with overlapping tiles and IoU deduplication. The selfie path still uses a single pass. Tile size, maximum tile count, and global size are configurable. Detection version is stored per photo.                                                                                                                                                                                                                                                                                                            |
| Alignment/model input | YuNet's five landmarks are used in the order expected by the InsightFace 112-pixel template. AuraFace ONNX has `[N,3,112,112]` input and begins with a convolution, with no embedded normalization. The code converts BGR crops to RGB, applies `(pixel - 127.5)/127.5`, and supplies NCHW float32. The same model manager processes photos and selfies. Embeddings are finite, 512-dimensional, and L2 normalized. Recognition preprocessing was intentionally kept at `auraface-rgb-112-v1`.                                                                                                                          |
| Quality               | Existing size/blur/exposure checks can reject usable difficult faces, especially faces below 48 pixels. Diagnostics now expose the individual rejection. These cutoffs were not relaxed without labeled evidence.                                                                                                                                                                                                                                                                                                                                                                                                       |
| Storage               | Previously only model version was stored. Face embeddings and searches now also carry preprocessing version, and photos carry detection version. Old embeddings are retained during reindexing; incompatible versions are excluded from search.                                                                                                                                                                                                                                                                                                                                                                         |
| Search                | Cosine similarity is `1 - (embedding <=> query)`. Search is constrained to event, active photo, accepted face, exact model and preprocessing versions. It groups by photo with `MAX(similarity)`, applies the acceptance threshold after candidate scoring, orders descending, and pages stored results 100 at a time. The result cap default is now 1000, configurable up to 10000. The aggregate query performs an exact scan; the existing HNSW index is not used as an approximate nearest-neighbor candidate source in this query. Database latency and HNSW recall on populated wedding events remain unmeasured. |
| Guest access          | Matching approval is tied to the exact active model/preprocessing versions. Changing or revoking approval expires completed searches and downloads. Public endpoints expose no bounding boxes, embeddings, or diagnostic scores.                                                                                                                                                                                                                                                                                                                                                                                        |

The principal observed causes of missing photographs were the 2048-pixel derivative cap, single-scale detection, quality rejection, and the former 100-result local cap. Their relative contributions on real weddings have not been measured. The benchmark also reveals a serious recognition false-match problem at the existing threshold; lowering it would worsen guest safety.

Model contract references: [AuraFace V1](https://huggingface.co/fal/AuraFace-v1), [ONNX export](https://huggingface.co/imagent/auraface-onnx), [InsightFace ArcFace ONNX preprocessing](https://github.com/deepinsight/insightface/blob/master/python-package/insightface/model_zoo/arcface_onnx.py), [InsightFace alignment template](https://github.com/deepinsight/insightface/blob/master/python-package/insightface/utils/face_align.py), [OpenCV YuNet](https://docs.opencv.org/4.8.0/df/d20/classcv_1_1FaceDetectorYN.html).

## Implemented controls and diagnostics

- Admin, owner, and photographer roles can inspect a photo at `/dashboard/events/{eventId}/photos/{photoId}/diagnostics`. The page shows the authorized original/preview, detected boxes, confidence, landmarks, aligned crops, dimensions, quality, embedding status, indexed versions, and failure reason. A test selfie returns the expected photo's score and threshold decision. Calls are audited without storing the selfie or embedding.
- Current release control: authenticated owners/admins may privately search their event. Public search remains disabled until separately validated at system level and also enabled for the event. The historical event approval fields are not read.
- Guest selfie guidance now covers light, centering, camera distance, blur, and multiple faces. Server quality errors are surfaced as actionable messages.
- Search results use pagination and remain tied to the owning guest session and consent. Original and ZIP download authorization remains in place.

## Reproducible benchmark and measurements

The [ControlFace10K dataset](https://huggingface.co/datasets/HuMInGameLab/ControlFace10K) was downloaded locally and ZIP integrity checked. The same deterministic selection of 100 identities and three images each was used before and after. Fifty identities (150 images) form calibration, and disjoint fifty identities (150 images) form evaluation. The benchmark runs in a CPU-only container capped at four CPUs and 4 GiB. At the preexisting 0.64 threshold:

| Held-out evaluation metric             |        Baseline |         Phase 5 |
| -------------------------------------- | --------------: | --------------: |
| Image-level face detection proxy       |  150/150 (100%) |  150/150 (100%) |
| Usable-face images                     |         149/150 |         149/150 |
| Pair true positive / false positive    |        38 / 136 |        38 / 136 |
| Pair true negative / false negative    |    10,889 / 112 |    10,889 / 112 |
| Pair precision / recall                | 21.84% / 25.33% | 21.84% / 25.33% |
| False acceptance / rejection           | 1.234% / 74.67% | 1.234% / 74.67% |
| In-memory photo retrieval TP / FP / FN |     14 / 4 / 86 |     14 / 4 / 86 |
| In-memory retrieval precision / recall |    77.78% / 14% |    77.78% / 14% |
| Mean / P95 inference per image         |    143 / 197 ms |    146 / 199 ms |
| Mean CPU time per image                |          579 ms |          582 ms |
| Peak process RSS                       |         726 MiB |         691 MiB |

The difference in timing and memory is run-to-run variation, not an established performance gain. The dataset's portrait images do not trigger the large-photo tile path, so this benchmark cannot measure the intended group-photo benefit. Image-level detection is only a proxy because ControlFace10K has no face box ground truth. Its synthetic single-subject images are not wedding, glasses, occlusion, side-angle, lighting, demographic, or DSLR validation. The in-memory search timer excludes HTTP, PostgreSQL, storage, and download time. No real-world production accuracy improvement is claimed.

Reproduce with the locally downloaded ZIP (do not commit biometric images):

```sh
python services/face-ai/scripts/evaluate.py .run/controlface10k.zip --identities 100 --pairs-output .run/phase5-pairs.json > .run/phase5-report.json
python services/face-ai/scripts/calibrate.py .run/phase5-pairs.json --report .run/phase5-report.json --output .run/phase5-threshold-proposal.json --preprocessing-version auraface-rgb-112-v1
```

Run the first command in the face-ai environment with the local model volume and production-like CPU/memory limits. The calibration sweep found **no eligible threshold** that met 99% precision and 0.1% false acceptance while finding true positives. It writes a pending proposal only; it never changes production configuration.

The identity evaluator also accepts a local CSV manifest of consented, labeled single-subject images for separate identity-level calibration and evaluation. For group photographs, `services/face-ai/scripts/evaluate_detection.py` accepts a local JSON manifest of EXIF-oriented face boxes (`[{"image":"relative.jpg","boxes":[[x,y,width,height]]}]`) and reports box true/false positives and negatives, recall, precision, and detection latency at a configurable IoU threshold. Run it with `--image-root` pointing to the private image directory. Before approval, assemble representative consented wedding/group photographs with manually verified face boxes and person IDs, measure end-to-end event retrieval, and run the same baseline/after protocol. PostgreSQL approximate-versus-exact recall is not applicable to the current exact aggregate query; if approximate candidate retrieval is introduced, it needs a separate recall comparison before activation.

## Reindex and rollback

1. Back up PostgreSQL and private object storage. Apply the migration and deploy the new workers with the existing migration gate.
2. Dry-run `node apps/api/scripts/reindex-face-embeddings.cjs` in the API runtime with `DATABASE_URL`, `REDIS_URL`, and `FACE_MODEL_VERSION`. It prints the count. Add `--apply` to queue changed/missing detection versions. It reuses stored originals to build the 4096-pixel AI derivative, leaves originals untouched, retains the old embedding version until a replacement transaction succeeds, and can be rerun after interruption. Monitor failed processing jobs before approval.
3. Evaluate threshold candidates only on representative, consented, gallery-level evaluation data. Public guest release is controlled at system level; no per-event artifact upload is used.
4. To roll back matching immediately, use **Revoke approval** in event settings. That restores the prior threshold and expires guest searches/download jobs. For a code rollback, redeploy the previous images after restoring the compatible schema/database backup; do not drop columns while the new API is running. Retained older embeddings allow a previous compatible model to be reselected, subject to new approval.

## Remaining limitations

Real wedding photos and verified group face boxes were not supplied. No real-world detection recall, end-to-end precision/recall, DB search latency, indexing throughput, or subgroup error rates can honestly be reported. The 16-tile cap can leave areas uncovered on extremely large panoramas; diagnostics should flag these cases during review. The local benchmark's current false-positive rate is unacceptable for public guest delivery. Production guest matching must remain unapproved until representative evaluation establishes a safe operating threshold and the owner approves it.
